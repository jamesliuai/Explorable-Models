# External trial handoff

Status: prepared protocol; **no external results recorded**. The owner will arrange participants and publication. The implementation agents and this repository's development cases are not blind external participants.

## Freeze before recruiting

Record the exact package hashes from `release/preview/package-evidence.json`, host application revision, published documentation revision, browser/device and provider configuration. Choose two fresh agent configurations, fixed budgets and task order. Keep at least ten supported briefs and numerical fixtures outside the candidate agent's writable workspace. Do not copy development presets and call them held-out tasks. Each brief must require creation, one focused revision, a boundary/interaction check, and save/reopen. Include separate unsupported requests; exclude them from the supported success denominator.

Evaluate all twenty attempts, including failures. A success requires quantitative and representation agreement, preserved unrelated content, working interaction, and exact artifact reopen without human source repair. Record tool calls, elapsed time, tokens if available, retries, interventions and failure classification. The gate is at least 8/10 per configuration. Missing measurements stay missing. Reruns after fixes need fresh variants.

## Developer integrations

Recruit three developers unfamiliar with the source. Give them only the packed/published packages and quickstarts. Ask each to embed two independent instances, use one custom control, connect its agent tools, change a parameter, save/reopen, and dispose/recreate the session. Record prerequisite setup time separately; the proposed integration target is 30 minutes after setup. Record every undocumented intervention. At least two integrations should be in an actual application workflow with a follow-up task, not only a demo reaction.

## Intended users and accessibility

Recruit at least three intended users for parameter changes, comparison/inspection and save/reopen. Include keyboard-only operation and a manual screen-reader task using a declared platform/browser/assistive-technology combination. Observe confusion, missed feedback and repeated effort as well as completion. Automated axe checks are supporting evidence only. Record consent and minimize personal data; do not put participant identities or recordings into the package.

## Security and performance

Have a reviewer who did not implement the boundaries assess the interpreter, renderer, worker protocol, relay and artifact importer. Supply the automated regression cases and retain reviewer findings and fixes. Separate-agent code review in this preview is automated engineering review, not the independent human security sign-off.

Measure the frozen workloads on a real mobile device as well as the recorded desktop. Preserve startup, p50/p95 interaction latency, CPU/render cost, memory time series, hidden-tab recovery and disposal results. A browser viewport and one heap sample cannot substitute for device and memory-stabilization evidence.

## Comparison study

Use three matched tasks with ordinary generated application code and this toolkit under the same agent/configuration/budget. Record creation and subsequent revision effort, failures and human repair. This is diagnostic engineering evidence; publish only claims supported by the recorded scope and limitations.

## Result template

For each attempt record: candidate hash; task ID (brief kept in evaluator storage); agent/host/model/settings; budget; start/end times; tool-call count; token usage or missing; created/revised/operated/reopened outcomes; fixture report; screenshot/representation review; intervention count/details; failure category; evaluator and review scope; repeat variant ID. Preserve artifacts and failed attempts, and redact secrets before sharing.

Fill the remaining checklist in `agent-first-release-status.md` with links to actual evidence. Do not change an open gate to passed merely because a protocol, test, or sample application now exists.
